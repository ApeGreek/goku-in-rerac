# RAC1 render pipeline survey (level01.elf overlay + SCUS_971.99)

The level overlays carry a full copy of the engine; `level01.elf` has the good C++ symbol names, and each file's header comment gives the matching boot address ("Lombyte exact-boot-match: boot 0x…"). Addresses below are level01 unless noted.

## 1. VU microprogram uploads

Two mechanisms, both citing `chunk0_addr − 0x10` / `− 0x8` (i.e. the DMAtag+VIFcode header that precedes the payload named in vu_microprograms.md):

* `VU0_loadMicroProgram__FPl` — `002b4470_VU0_loadMicroProgram__FPl.c` (boot `0x002334d8`, exported there as `start_vif1_dma_transfer`, a misnomer). Kicks **VIF0/D0** (`REG_DMAC_0_VIF0_TADR = addr & 0xfffffff`, `CHCR = 0x145` = chain+TTE+STR) and spins on `CHCR & 0x100`. Callers/args: `00264c30_DrawMobysSetup__Fv.c` → `0x100080` (prog **0x100090**); `0021a1b8_DrawDebugProfiler.c:177` (end of frame), `00255958_FUN_00255958.c:116` (level init), boot `001eb410_transition_default_draw.c`, boot `001e9b10` → `0x100ae0` (prog **0x100af0**); `002521a0_InitOnce__Fv.c:67` → `0x10e4c0` (prog **0x10e4d0**, the odd 0x0C80-offset patch). These three are the VU0-side programs (all ≤ 0xF70 bytes, i.e. they fit VU0's 4 KiB).
* VU1 programs are **embedded in the VIF1 chain** as REF DMA tags. Either via `VU1_addDataRef__FPvi` (`002b47c8`, writes `qwc|0x30000000` + address), or hand-written into the scratchpad-built chain as `CONCAT22(0x3000, *(u16*)(addr-0x10))` + `addr`. Assignments found:
  * `002a7e58_TfragProc.c:170` → `0x103570` (prog **0x103578**, 8 chunks) = main tfrag program; `:266` → `0x107020` (prog **0x107028**) for its second/fallback strip list.
  * `002a9a90_TieProc.c` → `0x108e20` (**0x108e28**) and `0x10ad20` (**0x10ad28**).
  * `0029cdf0_ShrubProc.c:266` → `0x101760` (**0x101768**); `:760` → `0x1022e0` (**0x1022e8**).
  * `0027c878_PartProc.c:453` → `0x101080` (**0x101088**) = particles.
  * `00264c30_DrawMobysSetup__Fv.c:8` and `0021a1b8:83` → `VU1_addDataRef(0x10faa0, uRam0010fa90)` (**0x10faa8**, 6 chunks) = **moby** renderer; tagged `DAT_0015f5e0 = 6`.
  * `0021e340_fun_001f76a0.c:42`, `002b8f98_FUN_002b8f98.c:35` → `0x10e810` (**0x10e818**) = textured-sprite/billboard program, tagged `DAT_0015f5e0 = 7`; particles use id 8.
  `DAT_0015f5e0` is the "VU1 program currently resident" cache (reset to −1 at frame start in `0021a1b8`).

## 2. Per-frame entry and renderer order

Main loop: `00259c40_entry.c`. Each iteration: `VU1_sendChain__Fv` (`002b4638`, kicks last frame's chain on D1 via `sce_dma_send`, sets sync mask `uGpffffa5a0 |= 0x1f`), `VU1_swapChain__Fv` (`002b45c8`, toggles `DAT_001611d0` between chain buffers `DAT_001611b8/bc`), `PutDrawBufferSmall__Fv`, `FUN_00223260`, `PutDrawBufferLarge__Fv`, then a `switch (DAT_0015f5c4)` on game mode; mode 6 → `002a57f0_dispatch_game_state_update` → **`0021a1b8_DrawDebugProfiler`** (boot `001f39d0`) — this is really `DrawWorld`/the frame render function; mode 4 → `002a3b90_fun_0022f288` (pause/freeze variant), mode 5 → `002b4020_FUN_002b4020`. Loop ends with `VU1_syncChain__Fi(1)`.

Order inside `0021a1b8` (gated by mask `DAT_0015f3f4`): `append_gif_transfer_packet` → `UpdateOcclusion` → `ResetGsRegisters` → **sky** (`FUN_00252570` → `FUN_0029ee10`/`FUN_0029edb0` = `UpdateSkyShellsAnimated`/`UpdateSkyShellsStatic`, chosen by the level index (== 1 → animated), not by NTSC/PAL; the standalone version is `FUN_0029f260`, which does `SetupSkyGifPaging` + up to 6 `SkyDrawShell__Fi(0029f668)`) → **tfrag** `DrawTfrag(002a7d30)` → irq tag `0x2010000` → **tie** `DrawTies_1(002a9770)` or `DrawTies_2(002a9838)` → `0x2020000` → **shrub** `DrawShrubs(0029cd40)` → `0x2040000` → fogged fullscreen sprite → **moby** `DrawMobys(00264e18)` → `0x2080000` → weapon/effect lists (`FUN_0021b030/0021b0a8/0021b120/0021b1e8` = registered draw-callback tables) → **particles** `PartProc(0027c878)` → AA/flip blit `FUN_00223200` (when `g_aa_enabled`) → HUD GS state `fun_00233c28` (A+D block 0x1c2970: TEST_1 0x5380b, ALPHA_1 0x44) → HUD/2D (mask 0x80: `FUN_0024fb50` slots + banner, `FUN_002266c0` help box, `FUN_001f4d98` screen fade) → `DoGifPaging` → mask 0x40: underwater tint and black/white fades (`emit_rgba_draw_packet`) → (order checked in `DrawWorld` 0x21a1b8, 2026-09-27; the HUD is drawn **after** the AA blit, docs/plan/hud_text.md) → `VU0_loadMicroProgram(0x100ae0)`. Then the **EE-side second half**, interleaved with `VU1_syncChain__Fi(2/4/8/0x10)`: `LightTfrags(0x1c5880)`+`PatchTfragGifs`, `LightTies(0x1c7780)`+`PatchTieGifs`, `FUN_0029e7e8(0x1bd430)` (LightShrubs)+`fun_00228a30`, `PatchMobyGifs`, `UpdateFog__Fi`. The irq tags come from `FUN_002b5110` (writes a CNT+IRQ tag `value-0x70000000`), matching the sync bits.

## 3. Chain builders per renderer

Common machinery (`002b4xxx`, boot `00233xxx`): `VU1_initChain`, `VU1_swapChain`, `write_vif_unpack_packet(002b4820)` (tag `qwc|0x10000000`, VIFcodes `0x1000404` STCYCL wl=4 cl=4 + `0x6c000000|size<<16|dst` UNPACK V4_32), `VU1_addGSregister(002b4918)` (2-qw DIRECT: GIFtag `0x8001`, NREG=1, REGS=0xE A+D), `VU1_setScissor(002b49d8)` (same, reg 0x40, clamped to `iRam0013e500/504`), `write_dma_channel(00221090)` = SPR_FROM (D8) copy scratchpad→main.

* **tfrag**: `DrawTfrag(002a7d30)` reserves 0x10 words for a NEXT tag, unpacks two 4-qw camera/matrix blocks to VU addrs 5 and 0x14d, calls `TfragProc(002a7e58)`, then `DmaTfragTextures(002a7b48)`, then `write_dma_channel(0x1c5880, 0x3000, 0x40)` (0x40 qw of visible-list from scratchpad 0x70003000 to 0x1c5880). `TfragProc` streams 0x40-byte tfrag headers into SPR at `0x70001000/0x70001800` (D9 SPR_TO, 0x800 bytes = 0x20 headers per burst), culls with VU0 macro ops, builds VIF1 packets in `0x70002000..0x70003000` (double-buffered with `^0x800`), pulls the ad-gif table (`0x1c5480`, 0x38 qw at SPR 0x3780) and flushes with D8. LOD is selected from the per-tfrag byte fields and distance table set by `SetTfragDists(002a79f0)`.
* **tie**: `DrawTies_1/2` → `TieProc(002a9a90)` → `write_dma_channel(0x1c7780|0x1c8980, 0x3600, 0x40)`; `DrawTies_2` is the PAL-only variant (`iGpffff8180` is the PAL flag 0x15ed80; not a mirror/reflection pass), toggling bit 3 of each instance's flags at +0x24 and copying buffers (`FastMemCopy(0x1c8780,0x1c7580,0x200)`, `(0x1c8380,0x1c6f80,0x400)`). Textures: `dma_tie_textures(002a94e8)` → `FUN_002aaf68` (unnamed = BuildTieTextureDma) + `FUN_002b4b00` (restore 3 GS regs from `0x1c3380`).
* **shrub**: `DrawShrubs(0029cd40)` → `ShrubProc(0029cdf0)` → `write_dma_channel(0x1bd430,0x3200,0x40)`, `dma_shrub_textures(0029caf8)`.
* **moby**: `DrawMobys(00264e18)` = `DrawMobysSetup` (adds the moby VU1 program, `VU1_addGSregister(0x47,0x5360b)`, records chain start `DAT_0015ffcc`) + `MobyProc(0026a7a0)` + `DrawMobysCleanUp(00264d68)`; `DrawMobyList(00264ce8)` is the re-entrant per-list version; overflow is checked against `DAT_001611c8`.
* **TEX0 fixup** (item 5, second half): `PatchTfragGifs(002a7c90)` walks the ad-gif lists (stride 0x14 words = 5 qw) and ORs the real TBP0 into `TEX0` bits 0..13 from table `0x1c5180` (pairs of u16 = TBP, CBP), CBP at +0x30. `PatchTieGifs(002a9628)` uses table `0x1c6f80`, index byte at +0x33, CBP at +0x20. `PatchMobyGifs(002648b0)` uses `0x19a300`, ad-gif stride 0x40, TEX0 at +0x30 and CLUT at +0x40.

## 4. GS state

`ResetGsRegisters__Fv(0021a050)` emits two A+D DIRECT blocks: 19 regs from **0x13cfc0** and 11 regs from **0x13cf10**, then FOGCOL (`0x3d`) from `DAT_0016d0f0/f4/f8`. That table is filled by `SetPalMode__Fi(00219cd0)`: FRAME at 0x13cf20 (`fbp = fb>>13`, `fbw = width>>6`), ZBUF at 0x13cf40 (`zbp>>13 | 0x1000000` = PSMZ24) and a ZMSK'd copy at 0x13d170 (`|0x101000000`), XYOFFSET at 0x13cf60/70 (`(0x800±ofs)*16`), SCISSOR at 0x13cf80. NTSC: frame `0x0e0000`, zbuf `0x1b0000`, display `0x280000`, `SetupFS_AA_buffer(0x200,0x1a0,0x200,0x1c0,0,0)` = 512×416 draw / 512×448 display; PAL: `0x100000`/`0x1e0000`/`0x2c0000`, `(0x200,0x1c0,0x200,0x200,4,0)` = 512×448/512×512. `sce_gs_reset_graph(0,1,mode,0)` is called from `002521a0_InitOnce__Fv.c:64` with mode 2 (NTSC) / 3 (PAL), interlace=1, ffmd=0 → SetGsCrt(1, 2|3, 0). Per-primitive state goes through `VU1_addGSregister`: TEST_1 `0x47` = `0x5360b` (ATE GEQUAL 0x60 + ZTE GEQUAL) for opaque, `0x3004b`/`0x2004b`/`0x31801` for UI and alpha passes; ALPHA_1 `0x42` = `0x8000000044` (Cs,Cd,As,Cd) most used, `0x8000000064`/`0x2000000064`/`0x44`; CLAMP_1 `0x08` = 0 or 5; TEX1_1 `0x14` = `0xff9000000260`; FBA `0x4a`, FRAME `0x4c` (`0x80070/0x80080`), ZBUF `0x4e`, RGBAQ `0x01`, TEX0 `0x06`. Full-screen AA/field resolve packets are pre-built at **0x151900 / 0x151b60 / 0x151bc0 / 0x151dc0 / 0x152040** by `SetupFS_AA_buffer(002224f8)` and emitted by `FUN_00223200` (38 regs @0x151900), `FUN_00223260` (41 regs @0x151b60), `append_gif_transfer_packet(00222ee8)` (21 regs @0x152040).

## 5. Texture uploads

`BuildTfragTextureDma(002a8bf0)` builds, in scratchpad `0x70002000..0x70002300`, per-texture GIF A+D blocks ending in TRXDIR `0x53` (index 0x12) with BITBLTBUF/TRXPOS/TRXREG filled from the log2 size in the top nibble of the `0x1c4e80` entry (`w=h=1<<n`), followed by an IMAGE GIFtag `((1<<n)*(1<<n))>>4 | 0x8000`; the usage bitmap is at `0x70003c00`, computed by `ComputeTfragTextureUsage(002a8a80)`. `DmaTfragTextures(002a7b48)` / `dma_tie_textures(002a94e8)` / `dma_shrub_textures(0029caf8)` / `DmaMobyTextures(002647a8)` all splice the resulting sub-chain into the VIF1 chain with NEXT tags `0x20000000` and complain past 0x400000 bytes. Generic 2D/HUD texture paging uses the same reserve/patch pattern: `SetupGifPaging__Fi(0021ac60)` reserves 4 qw, `DoGifPaging__Fv(0021ad78)` fills it and calls `fun_0020b4a8` + `FUN_002b4b00`; HUD banks go through `Hud_sendTexture__FPciiiii(002513b8)`, `Hud_SendResidentBank(0024ab28)`, particles through `_part_load_tex(0027d46c)`, startup font/image through `sce_gs_set_def_load_image`/`sce_gs_exec_load_image` (boot `00122330`/`00122658`, called in `SetPalMode` in 0x20×0x20 tiles).

## 6. VU0 macro-mode lighting

`LightTfrags(002a8e40)`, `LightTies(002ab218)` and `FUN_0029e7e8` (shrubs) are pure VU0 macro-mode (`_lqc2/_vmulbc/_vmaddabc/_vmulq/_vabs`) routines that read a **16-entry light bank at 0x00180340** (4 quadwords / 0x40 bytes per light; zeroed by `FastMemZero16(0x180340,0x400)` in `00255958`, together with `0x180740` (0x100) and `0x180940` (0x180)) and a constant vector `_DAT_0015fb40`, DMA the normal/light arrays into scratchpad via D9 SPR_TO (`LightTfrags`: SADR 0x3800, MADR 0x166500, QWC 0x100), and write packed RGBA back. Point lights are maintained by `UpdateAllPointLights(002528a8)` / `CreatePointLight(00252a28)` / `refresh_point_light(00252dd8)`; `FUN_002651a0` and `MobyProc` use the same 0x180340 bank for mobies. I found no explicit sine table at 0x70000000 — scratchpad 0x70000000–0x70000fff is used for chain headers and matrix staging (`DAT_70000000/04` tag, `0x70003f00` camera row, `0x700000a0`, `0x70000fe0` in ShrubProc); the "sine table" claim in tfrag_rac1.md is not corroborated by the EE code.
